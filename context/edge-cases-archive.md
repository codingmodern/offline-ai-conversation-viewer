# Edge Cases Archive

> Verbatim archive of edge cases formerly kept in `progress-tracker.md` Section §10.

| Edge Case                                                                                         | Discovered In Unit | Handling Strategy                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Skin ↔ data mismatch                                                                              | Design phase       | Documented as a business rule: skin and data source are independent. No error.                                                                                                                                                                                                                                                                                                                             |
| Missing `content` field in message                                                                | Design phase       | Render `[پیام بدون محتوا]` instead of crashing                                                                                                                                                                                                                                                                                                                                                             |
| Valid JSON that is semantically empty (`{}`, `[]`, `null`, whitespace-only)                       | Unit 01            | Rejected as `EmptyContentError`, separate message from `MalformedJsonError`                                                                                                                                                                                                                                                                                                                                |
| Drop payload containing no files (e.g. dragged text/image)                                        | Unit 01            | Ignored silently — no error row is created                                                                                                                                                                                                                                                                                                                                                                 |
| Same file imported twice in one session                                                           | Unit 01            | Each drop is an independent row keyed by request id; de-duplication belongs to the library (Unit 04)                                                                                                                                                                                                                                                                                                       |
| `Blob.prototype.text()` missing in jsdom                                                          | Unit 01            | Polyfilled in `tests/setup.ts` only; production code uses the native browser method                                                                                                                                                                                                                                                                                                                        |
| Valid JSON belonging to no supported platform                                                     | Unit 02            | `UnsupportedFormatError` — the file is rejected as a normal error row, not a crash                                                                                                                                                                                                                                                                                                                         |
| Two providers claiming the same file                                                              | Unit 02            | `AmbiguousFormatError`; matched ids logged to console only, generic message shown to the user                                                                                                                                                                                                                                                                                                              |
| A provider's `detect()` throwing on odd input                                                     | Unit 02            | Treated as "no match" and logged, so one buggy provider cannot break detection for the others                                                                                                                                                                                                                                                                                                              |
| DeepSeek export is an **array** of conversations, not a single object                             | Unit 02            | Signature requires the array wrapper; a bare conversation object is not claimed                                                                                                                                                                                                                                                                                                                            |
| Each RESPONSE's `inserted_at` precedes the REQUEST it answers                                     | Unit 03            | Order is taken from the `mapping` graph, never timestamps (ADR #4)                                                                                                                                                                                                                                                                                                                                         |
| Conversation-level `updated_at` later than every message's `inserted_at`                          | Unit 03            | Reported verbatim as `updatedAt`, never recomputed from `messages` — the platform records this field itself and the two legitimately differ, since a conversation can change without gaining a message (ADR #8)                                                                                                                                                                                            |
| Structural `mapping` node with `message: null` (the `root`)                                       | Unit 03            | Contributes no message instead of producing an empty bubble                                                                                                                                                                                                                                                                                                                                                |
| Regenerated answers: one node with several `children`                                             | Unit 03            | Flattened depth-first — every branch is kept, none silently dropped                                                                                                                                                                                                                                                                                                                                        |
| Cyclic or self-referential `children` in a malformed export                                       | Unit 03            | Each node visited once, so the walk terminates without duplicating messages                                                                                                                                                                                                                                                                                                                                |
| `children` id that has no matching node                                                           | Unit 03            | Skipped — there is no message to lose                                                                                                                                                                                                                                                                                                                                                                      |
| Conversation whose `mapping` holds only the root                                                  | Unit 03            | Parses to an empty message list; not an error                                                                                                                                                                                                                                                                                                                                                              |
| `mapping` with no literal `root` key                                                              | Unit 03            | Entry points derived from topology (nodes nobody lists as a child), so a _detected_ file always parses                                                                                                                                                                                                                                                                                                     |
| Multi-fragment message (one message, several `fragments`)                                         | Unit 03            | Each fragment becomes its own message, inheriting the parent's model/timestamp                                                                                                                                                                                                                                                                                                                             |
| Fragment `type` outside the 8 attested values                                                     | Unit 03            | Normalized to role `'unknown'`, `kind: 'text'`, raw type kept in `sourceFragmentType`; content preserved, never dropped (ADR #6/#7)                                                                                                                                                                                                                                                                        |
| Non-text fragments (`FILE`, `SEARCH`, `TOOL_SEARCH`, `TOOL_OPEN`, `TOOL_FIND`) carry no `content` | Unit 03            | **Bug found via a real DeepSeek export dated 2026-08-20 — not the test fixture, which only contained REQUEST/RESPONSE.** `content` was treated as a universal critical field, so these fragments raised `MissingFieldError` and blocked the whole import. Critical fields are now per-category: `content` only when `kind === 'text'`, `files` only when `kind === 'attachment'`, `results` never (ADR #7) |
| `TOOL_OPEN` / `TOOL_FIND` fragments with **no payload key whatsoever**                            | Unit 03            | Valid tool activity: `toolActivity.results` is omitted rather than defaulted to an empty value, so the model never claims results the export did not contain                                                                                                                                                                                                                                               |
| `FILE` fragment states no sender of its own                                                       | Unit 03            | Role inherited from its turn (the `REQUEST`/`RESPONSE` it arrived with), falling back to the closest preceding turn that states one; `'unknown'` when nothing in the export does                                                                                                                                                                                                                           |
| `FILE` fragment with more than one entry in `files[]`                                             | Unit 03            | All entries are mapped to `attachments[]`; nothing assumes exactly one file per fragment                                                                                                                                                                                                                                                                                                                   |
| Absent optional metadata (`title`, `inserted_at`, `model`)                                        | Unit 03            | Property omitted entirely (`exactOptionalPropertyTypes`), never set to `undefined` or a fabricated default                                                                                                                                                                                                                                                                                                 |
| One malformed conversation inside an otherwise valid export                                       | Unit 03            | The whole file fails with a path-tagged typed error rather than importing a partial, silently incomplete conversation                                                                                                                                                                                                                                                                                      |
| Importing a conversation that is already stored                                                   | Unit 04            | A dialog offers "Add anyway" / "Cancel"; **nothing is written until the user answers**, and neither auto-add nor auto-skip exists (FR9, ADR #9)                                                                                                                                                                                                                                                            |
| The same conversation appearing twice inside **one** file                                         | Unit 04            | Conversations are saved sequentially, so the second occurrence finds the first already stored and becomes a normal duplicate prompt — no special case                                                                                                                                                                                                                                                      |
| IndexedDB quota exhausted mid-save                                                                | Unit 04            | The Dexie transaction rolls back, so the existing library is untouched and no half-written record survives; surfaced as `StorageQuotaError` suggesting the user delete old conversations                                                                                                                                                                                                                   |
| `navigator.storage.estimate()` unavailable                                                        | Unit 04            | The 90% warning is skipped rather than guessed at, and the app relies on the atomic quota-error path instead (ADR #11)                                                                                                                                                                                                                                                                                     |
| `estimate()` reporting a zero or absent quota                                                     | Unit 04            | Treated as "no estimate available" instead of dividing by zero — a missing quota is not a full disk                                                                                                                                                                                                                                                                                                        |
| Deleting the conversation currently being read                                                    | Unit 04            | Confirmation first (FR6/FR7), then the adjacent conversation becomes active — next in Sidebar order, else previous, else Empty State (ADR #10)                                                                                                                                                                                                                                                             |
| Deleting a conversation that is **not** active                                                    | Unit 04            | The active selection is left alone; only the row disappears, so the user is not pulled out of what they were reading                                                                                                                                                                                                                                                                                       |
| A stored record whose conversation payload is malformed                                           | Unit 04            | `listConversations()` skips it rather than throwing, so one bad row cannot make the whole library unreadable; writes are validated up front so such a row cannot be created through the app                                                                                                                                                                                                                |
| Two conversations sharing the same `importedAt` millisecond (batch import)                        | Unit 04            | Sorted by `importedAt` then `id`, so the Sidebar order is total and stable instead of depending on IndexedDB's internal ordering                                                                                                                                                                                                                                                                           |
| An export with no `sourceConversationId`                                                          | Unit 04            | Rejected before the write with a typed validation error, because without it the duplicate key (ADR #9) could not be computed                                                                                                                                                                                                                                                                               |
| Explicit UI request with no backing state (\"open the import screen\")                                               | Unit 04            | User intent is stored (`useLibrary.isImporting`) and checked first by `AppShell`, never inferred from selection/library facts; guarded end-to-end by `tests/components/AppNavigation.test.tsx` |
| Successful import when nothing had ever been selected                                              | Unit 04            | The last conversation saved by that batch becomes active and the import screen yields to its placeholder; a duplicates-only batch skips silently, reports ONE summary, and changes nothing else (ADR #12, ADR #13)                                                                                                                                                                                          |
| Duplicate found during an import batch (was: "Add anyway" vs cancelled)                            | Unit 04            | Skipped automatically — never written, never prompted per item; ONE post-batch banner reports imported vs skipped counts, and the last saved (non-duplicate) conversation activates (FR8; FR9 as revised by ADR #13)                                                                                                                                                                                       |
| User asks to empty the whole library at once                                                       | Unit 04            | Exactly one destructive ConfirmDialog for the entire batch; on confirm `clearLibrary()` clears in one atomic transaction through `storage/` only; cancel writes nothing; success shows the genuine Empty State (`entries.length === 0`) (ADR #14)                                                                                                                                                           |
| App loads over a non-empty library with no selection this session                                  | Unit 04            | The newest conversation auto-activates on first load, so a reload can never reopen the "import your first file" screen over existing data (ADR #12)                                                                                                                                                                                                                                                       |
| Active record removed out-of-band while the app runs (direct DB edit)                              | Unit 04            | Defensive degradation only: the Empty State renders despite remaining records rather than a blank pane; unreachable through any app flow because import and initial load both activate a selection (ADR #12)
| A test's own `navigator.clipboard` stub is silently shadowed by user-event's internal EventTarget stub | Unit 06        | Copy-button assertions use `fireEvent.click` (plain dispatch) so the test's stub stays observable; recorded as a testing convention in Session 6 notes |
| Empty library when a search term is active                                                         | Unit 07        | The Sidebar defers to Unit 04's existing Empty State (`هنوز گفتگویی ذخیره نشده است.`) instead of inventing a parallel empty-state; the search bar is hidden on an empty/loading library because there is nothing to search |
| Non-Latin search text: Arabic-script look-alikes (ی/ي, ک/ك, hard vs soft) and Persian vs ASCII digits | Unit 07        | v1 matches **verbatim** after `toLowerCase()` only — Persian text survives byte-for-byte because the script has no case, but cross-spelling look-alikes do NOT match. This is the same pitfall family as Unit 05's `\d` vs `[۰-۹]`, accepted for v1 and pinned by an explicit test in `searchConversations.test.ts → matches Persian queries verbatim` |
| `liveQuery`-driven hook under `fake-indexeddb` seems to miss a follow-on write                        | Unit 07        | **Real root cause was the duplicate-key natural key (`sourceProvider`, `sourceConversationId`) silently dropping the second save via `saveConversation` returning `status: 'duplicate'` (Unit 04 / ADR #13)**, not a `liveQuery` race. The test's `makeConversation` defaulted `sourceConversationId` to `'conv-1'`, so the second fixture in the test collided with the first and was rejected. The fix is per-test `sourceConversationId: 't-...'`, never the fixture default. Recorded here so future search-index tests do not chase a phantom timing issue |
| An in-memory search index could drift from the underlying store if multiple subscribers race          | Unit 07        | Single source of truth: the index is built **inside** the same `liveQuery` projection Unit 04's `subscribeToLibrary` uses, so the live query itself is the synchronisation point. Two subscribers cannot see divergent snapshots because Dexie runs the query against the same storage state |
| The hidden+summary thinking variant cannot be exercised through the real-export fixture                               | Unit 09        | A real export shows that variant only on *dead* regenerate branches, which ADR #22's walk never visits. Pinned instead by an inline live-line fixture in `claude.parse.test.ts`; the shared fixture keeps the visible-body variant only |
| Claude's export omits `file_size` on most attachments (unlike DeepSeek)                                                | Unit 09        | The attachment size chip renders only when a size exists — never a fabricated `0 B`; `deepseek/AttachmentCard.tsx` gained the same conditional so both themes share the rule |
| Gemini's answer is stored as raw HTML, so the search haystack contains markup too                                       | Unit 10        | FR7 keeps the answer verbatim and the search layer reads the shared model provider-agnostically, so tags are searchable v1 behaviour — documented, not special-cased per provider |
