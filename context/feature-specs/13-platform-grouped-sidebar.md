# Spec: Unit 13 — دسته‌بندی سایدبار بر اساس پلتفرم (Platform-Grouped Sidebar)

## Goal
بازطراحی سایدبار کتابخانه (`Sidebar.tsx`) به‌گونه‌ای که گفتگوها به‌جای یک لیست تخت (flat) از همه‌ی پلتفرم‌ها با هم مخلوط، زیر یک گروه مجزا برای هر پلتفرم (Claude، ChatGPT، Gemini، DeepSeek) نمایش داده شوند — با هدف کاهش به‌هم‌ریختگی و مدیریت راحت‌تر کتابخانه‌ی چندپلتفرمی.

## User Flow
1. کاربر برنامه را باز می‌کند → سایدبار همیشه ۴ گروه پلتفرم را نمایش می‌دهد (چه گفتگویی داشته باشند چه نه).
2. هر گروه با آیکون اختصاصی پلتفرم + نام پلتفرم + تعداد گفتگوهای آن (صفر اگر خالی) در هدر خودش مشخص می‌شود.
3. کاربر روی هدر یک گروه کلیک می‌کند → آن گروه باز/بسته (collapse/expand) می‌شود.
4. وضعیت باز/بسته‌ی هر گروه بین بازدیدها حفظ می‌شود.
5. وقتی گفتگوی جدیدی import می‌شود، گروه مربوطه به‌روزرسانی (تعداد و ترتیب گروه‌ها) می‌شود.
6. کاربر در نوار جستجو تایپ می‌کند → نتایج جستجو، مستقل از گروه‌بندی بصری، اما هرکدام با نشان پلتفرم خودشان نمایش داده می‌شوند.

## Functional Requirements

**FR1 — نمایش همیشگی ۴ گروه**
سایدبار همیشه دقیقاً ۴ گروه پلتفرم (Claude، ChatGPT، Gemini، DeepSeek) را نمایش می‌دهد، مستقل از اینکه کتابخانه خالی باشد یا پر. ترتیب گروه‌های بدون‌گفتگو ثابت و از‌پیش‌تعریف‌شده است (الفبایی یا ترتیب معرفی در پروژه)، چون «آخرین گفتگو» برای گروه خالی معنا ندارد.

**FR2 — شمارنده و آیکون هر گروه**
هر هدر گروه شامل: آیکون اختصاصی پلتفرم (از همان مجموعه‌ی آیکون‌های موجود در `PlatformIcons.tsx`، Unit 08)، نام نمایشی پلتفرم، و تعداد گفتگوهای آن پلتفرم در کتابخانه (عدد صفر برای گروه خالی، بدون حذف یا خاکستری‌کردن غیرفعال‌کننده — گروه خالی هم باید قابل کلیک به سمت import باشد طبق FR6).

**FR3 — ترتیب گروه‌های غیرخالی**
گروه‌هایی که حداقل یک گفتگو دارند، بر اساس زمان **آخرین گفتگوی import‌شده** در آن پلتفرم مرتب می‌شوند (جدیدترین بالا). این ترتیب فقط در لحظه‌ی یک import جدید دوباره محاسبه می‌شود — انتخاب یا باز کردن یک گفتگوی موجود باعث تغییر ترتیب گروه‌ها نمی‌شود. گروه‌های خالی (FR1) همیشه بعد از گروه‌های غیرخالی، به ترتیب ثابت، قرار می‌گیرند.

**FR4 — Collapse/Expand با یادآوری وضعیت**
این قانون فقط برای گروه‌های غیرخالی صدق می‌کند. کلیک روی هدر یک گروه غیرخالی آن را باز/بسته (collapse/expand) می‌کند. وضعیت باز/بسته‌ی هر گروه به‌ازای هر پلتفرم در `localStorage` ذخیره می‌شود و در بازدیدهای بعدی همان وضعیت بازیابی می‌شود. مقدار پیش‌فرض (در نبود مقدار ذخیره‌شده) برای همه‌ی گروه‌ها «باز» است.

**FR5 — یکپارچگی با جستجوی موجود (Unit 07)**
نتایج جستجو (کامپوننت `SearchResultsList`) همچنان به‌صورت یک لیست واحد نمایش داده می‌شوند (نه دسته‌بندی‌شده زیر گروه پلتفرم)، اما **هر نتیجه باید نشان پلتفرم خودش را حمل کند** (همان آیکون اختصاصی پلتفرم، کنار عنوان گفتگو) تا کاربر فوراً بفهمد نتیجه‌ی جستجو مربوط به کدام پلتفرم است. رفتار جستجو (matching، scope) از Unit 07 بدون تغییر باقی می‌ماند — این صرفاً یک تغییر بصری در رندر نتیجه است.

**FR6 — نقطه‌ی ورود import از گروه خالی**
گروه خالی اصلاً قابلیت باز/بسته‌شدن ندارد (FR4 برایش معنا ندارد، چون بدنه‌ای برای expand کردن وجود ندارد). کل هدر گروه خالی خودش دکمه‌ی ورود به Import است — بدون chevron، بدون دکمه‌ی جدا — و کلیک روی آن کاربر را مستقیماً به فلوی Import با پلتفرم از‌پیش‌انتخاب‌شده (گام Platform Selection در Unit 08 رد می‌شود) هدایت می‌کند.

## Non-functional Requirements
- NFR1: تغییر صرفاً در لایه‌ی UI سایدبار است؛ مدل داده (`UnifiedConversation`)، منطق تشخیص پلتفرم، و لایه‌ی `storage/` دست‌نخورده باقی می‌مانند (FR3 پروژه — جداسازی مرزها).
- NFR2: گروه‌بندی باید از داده‌ی موجود (`sourceProvider` روی هر رکورد) مشتق شود؛ هیچ فیلد جدیدی به مدل داده افزوده نمی‌شود.
- NFR3: عملکرد باید با کتابخانه‌های بزرگ (۱۰۰+ گفتگو، طبق مرجع واقعی DeepSeek) قابل قبول بماند — گروه‌بندی باید از طریق `liveQuery` موجود (Unit 04) مشتق شود، نه یک کوئری جداگانه به Dexie.

## UI Behavior
- هر هدر گروه از نظر بصری شبیه به یک Accordion است: آیکون شورون (chevron) برای نشان‌دادن وضعیت باز/بسته، در کنار آیکون پلتفرم و شمارنده.
- گروه خالی با همان استایل گروه‌های دیگر نمایش داده می‌شود، فقط با یک پیام کوتاه داخلش به‌جای لیست گفتگو (مثلاً «هنوز گفتگویی از Gemini وارد نشده») + دکمه‌ی import طبق FR6.
- انیمیشن باز/بسته‌شدن گروه باید `prefers-reduced-motion` را رعایت کند (طبق الزامات دسترس‌پذیری موجود پروژه در `ui-context.md`).

## Validation
- اگر مقدار ذخیره‌شده‌ی collapse-state در `localStorage` خراب/نامعتبر باشد → به حالت پیش‌فرض «همه باز» برمی‌گردد (بدون کرش).

## Edge Cases
- پلتفرمی که در حال حاضر `available: false` نیست (یعنی هر ۴ پلتفرم) — همه باید گروه فعال داشته باشند؛ این Unit هیچ گروهی برای پلتفرم ثبت‌نشده (`ProviderId` آینده) اضافه نمی‌کند.
- کاربری که همه‌ی گفتگوهای یک پلتفرم را حذف می‌کند (`DeleteConversationDialog` یا `ClearLibraryDialog`) → آن گروه به حالت خالی (FR1/FR6) برمی‌گردد، نه حذف می‌شود.
- دو گفتگو از دو پلتفرم مختلف با زمان import یکسان (نظری) → ترتیب گروه‌ها با یک قاعده‌ی ثانویه‌ی ثابت (مثلاً ترتیب الفبایی) مشخص می‌شود.

## Acceptance Criteria
- [ ] باز کردن برنامه با کتابخانه‌ی خالی → هر ۴ گروه پلتفرم با شمارنده‌ی صفر و آیکون مخصوص خودشان نمایش داده می‌شوند.
- [ ] Import یک گفتگوی DeepSeek → گروه DeepSeek شمارنده‌اش افزایش می‌یابد و (اگر جدیدترین import باشد) به بالای لیست گروه‌های غیرخالی می‌رود.
- [ ] بستن یک گروه، رفرش صفحه، گروه همچنان بسته می‌ماند.
- [ ] جستجوی یک عبارت موجود در گفتگوهای دو پلتفرم مختلف → هر دو نتیجه در یک لیست با آیکون پلتفرم مجزا نمایش داده می‌شوند.
- [ ] کلیک روی گروه خالی Gemini → کاربر مستقیم به فلوی import با پلتفرم Gemini از‌پیش‌انتخاب‌شده می‌رسد.
- [ ] حذف همه‌ی گفتگوهای یک پلتفرم → گروهش به حالت خالی برمی‌گردد، نه ناپدید می‌شود.
