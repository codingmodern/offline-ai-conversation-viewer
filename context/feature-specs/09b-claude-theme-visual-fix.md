# Spec اصلاحی: Unit 09b — هماهنگ‌سازی بصری تم Claude با UI واقعی

> **مرجع:** اسکرین‌شات‌های واقعی از claude.ai (۳ عکس، توسط کاربر تهیه شده)
> **وابستگی:** Unit 09 (Claude Platform Parser & Renderer) — این یک اصلاح بصری روی همان کامپوننت‌هاست، نه واحد جدید
> **دامنه:** فقط `src/themes/claude/` — بدون تغییر در پارسر/نرمال‌سازی

---

## 1. Goal

اصلاح مغایرت‌های بصری بین تم فعلی Claude در برنامه و ظاهر واقعی claude.ai که در بازبینی کاربر شناسایی شد (رنگ و چیدمان به‌هم‌ریخته در باکس‌های پیام کاربر/مدل).

---

## 2. مغایرت‌های شناسایی‌شده (از روی اسکرین‌شات‌های واقعی)

| # | المان | وضعیت فعلی احتمالی (نیاز به بررسی Cline) | وضعیت صحیح (طبق اسکرین‌شات) |
|---|-------|------------------------------------------|------------------------------|
| 1 | **حباب پیام کاربر (human)** | نامشخص/نادرست | حباب با پس‌زمینه خاکستری تیره‌ی ملایم (نه رنگ برند)، گوشه‌های گرد بزرگ (`rounded-lg` معادل)، **راست‌چین**، عرض محدود به محتوا (max-width حدود ۶۰-۷۰٪ عرض کانتینر)، بدون border مشخص |
| 2 | **پیام دستیار (assistant)** | احتمالاً به اشتباه حباب‌دار شده | **بدون حباب و بدون پس‌زمینه** — متن مستقیم روی پس‌زمینه‌ی صفحه، تمام‌عرض (نه محدود)، چپ‌چین از ابتدای ستون محتوا |
| 3 | **بلوک Thinking** | احتمالاً باکس بزرگ/پررنگ | خط بسیار کم‌حجم و کم‌رنگ: فقط متن «Thought for Ns» با رنگ `--text-muted`، بدون border یا background جدا؛ در حالت باز شدن هم نباید باکس سنگین بشه |
| 4 | **آیکون‌های اکشن زیر پیام** | نامشخص | ردیف افقی کوچیک از آیکون‌ها (کپی، صدا/خواندن، لایک/دیس‌لایک، اشتراک‌گذاری، regenerate) + تاریخ، همه با رنگ خاکستری کم‌رنگ، **فقط زیر پیام‌های assistant** |
| 5 | **رنگ برند نارنجی (`--brand-claude` / Clay Orange)** | احتمالاً جاهای اشتباه استفاده شده (مثلاً پس‌زمینه حباب) | فقط روی لوگوی ستاره‌ای (۸ پَر) و المان‌های هویتی برند — **نه** روی حباب پیام یا پس‌زمینه‌ی عمومی |
| 6 | **تایپوگرافی** | نامشخص | عنوان/لوگو با فونت **Serif**؛ متن چت با فونت **Sans-serif** معمولی — این دو نباید قاطی بشن |
| 7 | **پس‌زمینه کلی صفحه چت** | نامشخص | مشکی خیلی تیره ولی نه `#000000` مطلق (نزدیک `#1a1a1a` تا `#212121`) |
| 8 | **فاصله‌گذاری بین پیام‌ها** | نامشخص | فاصله‌ی عمودی سخاوتمندانه بین پیام‌ها، بدون خط جداکننده (divider) بین حباب کاربر و پاسخ assistant |

## 3. Functional Requirements

| # | نیازمندی |
|---|----------|
| FR1 | حباب پیام کاربر و بلوک پیام assistant باید ساختار بصری کاملاً متفاوتی داشته باشند (طبق جدول بخش ۲، ردیف ۱-۲) — نه یک قالب یکسان با رنگ متفاوت |
| FR2 | بلوک Thinking باید به‌صورت یک خط متنی کم‌حجم (نه کارت/باکس با border) رندر شود، چه در حالت بسته چه باز |
| FR3 | رنگ `--brand-claude` (Clay Orange) باید محدود به المان‌های برند شود (لوگو، آیکون فعال/انتخاب‌شده در سطح پلتفرم)؛ حباب پیام کاربر از یک رنگ خنثی (خاکستری تیره از پالت `ui-context.md`) استفاده کند |
| FR4 | فونت Serif فقط برای عنوان/برندینگ استفاده شود؛ تمام متن پیام‌ها (کاربر و assistant) از فونت Sans-serif اصلی پروژه استفاده کنند |
| FR5 | آیکون‌های اکشن (کپی/regenerate/تاریخ) فقط زیر پیام‌های assistant نمایش داده شوند، با استایل کم‌رنگ و کوچک |

---

## 4. Validation

- تغییرات فقط باید در فایل‌های تم Claude (`tokens.css`, `ClaudeMessage.tsx` و فایل‌های CSS Module مرتبط) اعمال شوند.
- هیچ تغییری در تم DeepSeek یا کامپوننت‌های مشترک (`AppShell`, `MetadataPanel`) نباید رخ دهد.
- بعد از اصلاح، خروجی باید با اسکرین‌شات‌های ضمیمه از نظر ساختار کلی (نه پیکسل‌به‌پیکسل) قابل تطبیق باشد.

---

## 5. Acceptance Criteria

- [ ] پیام کاربر: حباب راست‌چین با پس‌زمینه خاکستری خنثی، بدون رنگ برند
- [ ] پیام assistant: بدون حباب، تمام‌عرض، بدون پس‌زمینه مجزا
- [ ] بلوک Thinking: نمایش کم‌حجم مطابق الگوی «Thought for Ns»، بدون باکس سنگین
- [ ] رنگ نارنجی برند فقط در لوگو/عناصر هویتی دیده می‌شود، نه در حباب‌های پیام
- [ ] فونت عنوان Serif و فونت بدنه Sans-serif به‌درستی از هم تفکیک شده‌اند
- [ ] آیکون‌های اکشن فقط زیر پیام‌های assistant و با استایل کم‌رنگ دیده می‌شوند
- [ ] `npm run build` / `lint` / `test` بدون خطای جدید پاس می‌شوند
- [ ] هیچ تغییری در تم DeepSeek یا پارسر/نرمال‌سازی Claude رخ نداده است

---

## 6. یادداشت برای Cline

سه اسکرین‌شات واقعی از claude.ai همراه این Spec ارسال می‌شود. لطفاً قبل از هرگونه تغییر:
1. کامپوننت‌های فعلی تم Claude (`ClaudeMessage.tsx`, `tokens.css`, و CSS Module های مرتبط) را مرور کن و دقیقاً مغایرت‌های فعلی را نسبت به جدول بخش ۲ فهرست کن.
2. لیست مغایرت‌های واقعی (نه فرضی) را قبل از شروع اصلاح گزارش بده — طبق قانون پروژه «رفتار را حدس نزن».
