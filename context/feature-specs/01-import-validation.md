# Feature Spec: Import & Validation

> **Unit:** 01 — Import & Validation
> **Depends on:** ندارد (اولین واحد پیاده‌سازی پروژه)
> **Maps to Feature:** #1 در فهرست Featureهای تأییدشده

---

## Goal

فراهم کردن یک مکانیزم امن و کاربرپسند برای باز کردن فایل(های) JSON خروجی‌گرفته‌شده از پلتفرم‌های AI، به‌گونه‌ای که فایل قبل از ورود به مراحل بعدی (Detection/Parsing) به‌درستی خوانده شده و به‌عنوان JSON معتبر و غیرخالی تأیید شود — بدون اینکه هرگز اپلیکیشن Crash کند یا فایل نامعتبر وارد جریان بعدی شود.

> **مرز مسئولیت:** این واحد **فقط** اعتبار نحوی (Syntax) و غیرخالی‌بودن فایل را بررسی می‌کند. تشخیص اینکه آیا محتوای فایل متعلق به یکی از پلتفرم‌های پشتیبانی‌شده است یا نه، به‌طور کامل و منحصر به Unit 02 (Platform Auto-Detection) واگذار شده است؛ این واحد هیچ بررسی «شباهت به فرمت پلتفرم» انجام نمی‌دهد.

---

## User Flow

1. کاربر از طریق دو مسیر فایل را وارد می‌کند: کلیک روی دکمه‌ی Import (باز کردن File Picker سیستم‌عامل) یا Drag & Drop فایل(های) روی ناحیه‌ی مشخص‌شده‌ی اپلیکیشن.
2. اپلیکیشن وضعیت **Reading** را نمایش می‌دهد (فایل از دیسک به حافظه خوانده می‌شود).
3. محتوای فایل به‌عنوان متن خام خوانده و تلاش می‌شود به JSON Parse شود.
4. در صورت موفقیت Parse خام JSON (نحو معتبر و غیرخالی)، فایل آماده‌ی انتقال به مرحله‌ی بعدی است. تشخیص اینکه ساختار متعلق به کدام پلتفرم است یا اصلاً پشتیبانی می‌شود یا نه، در Unit 02 انجام می‌شود.
5. اگر فایل معتبر (JSON قابل‌Parse و غیرخالی) باشد → وضعیت **Success** و فایل Validate‌شده به‌عنوان ورودی به Pipeline تشخیص پلتفرم (Unit 02) منتقل می‌شود.
6. اگر فایل نامعتبر باشد (خراب، غیر-JSON، خالی، یا بیش از حد بزرگ) → پیام خطای کاربرپسند نمایش داده می‌شود و فایل رد می‌شود؛ فایل‌های دیگر (در صورت Import چندگانه) همچنان پردازش می‌شوند.
7. کاربر می‌تواند چند فایل را هم‌زمان انتخاب/Drop کند؛ هر فایل مستقل پردازش و نتیجه‌ی هرکدام (موفق/ناموفق) جداگانه به کاربر نمایش داده می‌شود.

## Functional Requirements

| # | Requirement |
|---|-------------|
| FR1 | کاربر باید بتواند فایل را از طریق File Picker انتخاب کند |
| FR2 | کاربر باید بتواند فایل(ها) را با Drag & Drop روی ناحیه‌ی مشخصی از صفحه وارد کند |
| FR3 | سیستم باید امکان انتخاب/Drop چند فایل هم‌زمان را پشتیبانی کند |
| FR4 | فقط فایل‌های با پسوند/محتوای `.json` پذیرفته می‌شوند |
| FR5 | خواندن و Parse اولیه‌ی فایل باید در Web Worker انجام شود تا از Block شدن UI جلوگیری شود (طبق Invariant پروژه) |
| FR6 | سیستم باید ساختار JSON را از نظر معتبر بودن نحوی (Syntax) و غیرخالی‌بودن اعتبارسنجی کند؛ هیچ بررسی مربوط به تشخیص پلتفرم در این واحد انجام نمی‌شود |
| FR7 | در صورت موفقیت Validation، فقط فایل Validate‌شده (و نه هیچ داده‌ی دیگری) به Pipeline تشخیص پلتفرم (Unit 02) منتقل شود؛ این واحد هیچ داده‌ای مستقیماً به کتابخانه (Library) اضافه نمی‌کند |
| FR8 | در صورت شکست Validation در هر مرحله (خواندن فایل، Parse JSON، بررسی غیرخالی‌بودن)، خطا با نوع مشخص (`ParseError` دسته‌بندی‌شده) بازگردانده شود |

## Non-Functional Requirements

| # | Requirement |
|---|-------------|
| NFR1 | Parse یک فایل معمولی (زیر ۵ مگابایت) باید کمتر از ۱ ثانیه طول بکشد |
| NFR2 | Parse فایل بزرگ (تا ۵۰ مگابایت) باید در Web Worker انجام شود و UI در طول آن کاملاً Responsive بماند |
| NFR3 | خواندن/Parse فایل نباید هیچ درخواست شبکه‌ای ایجاد کند (طبق Invariant #1 پروژه) |
| NFR4 | فرآیند Import باید برای چند فایل هم‌زمان مقیاس‌پذیر باشد؛ فایل‌های مستقل نباید یکدیگر را Block کنند |

## UI Behavior

| وضعیت | نمایش |
|-------|-------|
| **Idle** | ناحیه‌ی Drag & Drop با راهنمای واضح («فایل‌های JSON را اینجا رها کنید یا کلیک کنید») |
| **Dragging** | تغییر بصری ناحیه (Highlight/Border) هنگام کشیدن فایل روی آن |
| **Reading/Parsing** | نشانگر Progress یا Spinner به‌ازای هر فایل در حال پردازش؛ در Import چندگانه، وضعیت هر فایل جداگانه نمایش داده می‌شود |
| **Success** | فایل Validate‌شده به Pipeline تشخیص پلتفرم (Unit 02) تحویل داده می‌شود؛ این واحد مسئول افزودن به کتابخانه یا نمایش در Sidebar نیست |
| **Error** | پیام خطای کاربرپسند طبق «Error Handling Standards» (`code-standards.md`) — بدون Stack Trace یا جزئیات فنی خام؛ فایل‌های دیگر در همان دسته‌ی Import تحت تأثیر قرار نمی‌گیرند |

## Validation

| بررسی | نحوه‌ی اعمال |
|-------|----------------|
| **پسوند/نوع فایل** | فقط `.json` یا MIME Type متناظر پذیرفته می‌شود |
| **اعتبار نحوی JSON** | تلاش برای Parse امن در Worker؛ شکست → `ParseError` نوع `MalformedJsonError` |
| **ساختار غیر-خالی** | فایل نباید JSON خالی (`{}`, `[]`, `null`) باشد → `ParseError` نوع `EmptyContentError` |
| **اندازه‌ی فایل** | هشدار (نه رد قطعی) برای فایل‌های بسیار بزرگ (>۵۰ مگابایت) پیش از شروع Parse |

## Edge Cases

| سناریو | رفتار موردانتظار |
|--------|-------------------|
| فایل JSON خراب (Syntax Error) | خطای کاربرپسند «این فایل قابل خواندن نیست»؛ فایل رد می‌شود، اپ Crash نمی‌کند |
| فایل خالی (۰ بایت) | خطای کاربرپسند مشخص («فایل خالی است»)؛ رد می‌شود |
| فایل با پسوند غیر-JSON (مثلاً `.txt`, `.html`) | رد فوری پیش از تلاش برای Parse، با پیام «فقط فایل JSON پشتیبانی می‌شود» |
| Import چند فایل هم‌زمان که برخی معتبر و برخی نامعتبرند | فایل‌های معتبر به Pipeline تشخیص پلتفرم منتقل می‌شوند؛ فایل‌های نامعتبر با پیام خطای مجزا مشخص می‌شوند؛ یک فایل خراب مانع پردازش بقیه نمی‌شود |
| فایل بسیار بزرگ (>۵۰ مگابایت) | هشدار پیش از Parse؛ اجرای Parse در Web Worker با نمایش Progress؛ در صورت شکست Parse (مثلاً کمبود حافظه)، خطای کاربرپسند مرتبط |
| Drag & Drop یک فایل غیر-فایل (مثلاً متن یا تصویر Copy شده) | نادیده گرفته شود یا پیام «نوع محتوای پشتیبانی‌نشده» نمایش داده شود |

## Acceptance Criteria

- [ ] کاربر می‌تواند از طریق File Picker یک یا چند فایل JSON را انتخاب کند
- [ ] کاربر می‌تواند فایل(ها) را با Drag & Drop وارد کند
- [ ] فایل JSON معتبر با موفقیت خوانده، Parse و **فقط** به Pipeline تشخیص پلتفرم منتقل می‌شود (بدون افزودن مستقیم به کتابخانه)
- [ ] فایل JSON نامعتبر (خراب یا خالی) با پیام خطای کاربرپسند رد می‌شود، بدون Crash اپلیکیشن
- [ ] Parse فایل‌ها در Web Worker انجام می‌شود و در طول آن UI Responsive می‌ماند
- [ ] Import چند فایل هم‌زمان پشتیبانی می‌شود و هر فایل نتیجه‌ی مستقل خودش را دارد
- [ ] هیچ درخواست شبکه‌ای در طول کل فرآیند ارسال نمی‌شود
- [ ] پیام‌های خطا هیچ جزئیات فنی خام (Stack Trace و ...) نمایش نمی‌دهند
- [ ] این واحد هیچ فایلی را به‌دلیل «عدم شباهت به یک پلتفرم شناخته‌شده» رد نمی‌کند — این تصمیم منحصراً در Unit 02 گرفته می‌شود
