# Spec: Unit 08 — Guided Import Flow (ورود مرحله‌ای فایل)

> **وابستگی:** Unit 01 (Import & Validation), Unit 02 (Platform Detection — به‌صورت service مستقل)
> **وضعیت:** تایید شده — آماده برای Implementation

---

## 1. Goal

جایگزینی ورودی فعلی import با یک جریان سه‌مرحله‌ای راهنما (Guided Flow) که ابتدا کاربر پلتفرم مبدأ چت را با انتخاب بصری (آیکون/لوگوی هر پلتفرم) مشخص می‌کند، سپس فایل مربوطه را آپلود می‌کند، و در نهایت پیش از ذخیره‌سازی نهایی، خلاصه‌ای از نتیجه import را می‌بیند. این جریان باعث کاهش خطای کاربر (آپلود فایل اشتباه) و بهبود وضوح تجربه کاربری می‌شود.

---

## 2. User Flow

1. کاربر روی دکمه/ورودی "Import Chat" کلیک می‌کند.
2. **Step 1 — انتخاب پلتفرم:** چهار کارت (ChatGPT، Claude، Gemini، DeepSeek) نمایش داده می‌شود؛ کاربر یکی را انتخاب می‌کند.
   - اگر DeepSeek انتخاب شود → دکمه "ادامه" فعال می‌شود.
   - اگر یکی از سه پلتفرم دیگر انتخاب شود → پیام "به‌زودی پشتیبانی می‌شود" نمایش داده می‌شود و دکمه "ادامه" غیرفعال می‌ماند.
3. کاربر روی "ادامه" کلیک می‌کند و وارد **Step 2 — آپلود فایل** می‌شود.
4. کاربر فایل export را از طریق drag & drop یا انتخاب دستی بارگذاری می‌کند.
5. سیستم به‌صورت خودکار پلتفرم واقعی فایل را تشخیص می‌دهد (با استفاده از منطق موجود در Unit 02) و با انتخاب Step 1 مقایسه می‌کند.
   - در صورت تطابق → کاربر به Step 3 هدایت می‌شود.
   - در صورت عدم تطابق → خطای واضح نمایش داده می‌شود و کاربر می‌تواند فایل دیگری انتخاب کند یا به Step 1 بازگردد.
6. **Step 3 — پیش‌نمایش/تایید:** خلاصه‌ای از نتیجه import (تعداد مکالمات یافت‌شده، موارد تکراری تشخیص‌داده‌شده) نمایش داده می‌شود.
7. کاربر تایید می‌کند → داده‌ها طبق منطق موجود Unit 01 (Dexie/IndexedDB) ذخیره می‌شوند و کاربر به Sidebar/Chat Library هدایت می‌شود.

کاربر در هر مرحله می‌تواند با دکمه "بازگشت" به مرحله قبل برگردد بدون از دست دادن انتخاب‌های قبلی.

## 3. Functional Requirements

| # | نیازمندی |
|---|----------|
| FR1 | نمایش ۴ کارت انتخاب پلتفرم (ChatGPT, Claude, Gemini, DeepSeek) با آیکون SVG اختصاصی هر کدام |
| FR2 | هر کارت دارای حالت‌های: عادی، hover، انتخاب‌شده (selected) |
| FR3 | انتخاب پلتفرم‌های غیر از DeepSeek، پیام اطلاع‌رسانی "به‌زودی" را فوراً (بدون نیاز به آپلود) نمایش می‌دهد |
| FR4 | دکمه "ادامه" در Step 1 فقط برای پلتفرم دارای پارسر (فعلاً DeepSeek) فعال می‌شود |
| FR5 | Step Indicator (نشانگر پیشرفت مراحل) در بالای فلو نمایش داده می‌شود و مرحله جاری را مشخص می‌کند |
| FR6 | Step 2 از منطق آپلود/اعتبارسنجی فرمت فایل موجود در Unit 01 استفاده مجدد می‌کند (بدون بازنویسی) |
| FR7 | تشخیص پلتفرم فایل آپلودی با استفاده از service مستقل‌شده Unit 02 انجام می‌شود |
| FR8 | در صورت عدم تطابق پلتفرم انتخابی (Step 1) با پلتفرم تشخیص داده‌شده از فایل، پیام خطای شفاف نمایش داده شود و import متوقف شود |
| FR9 | امکان بازگشت به مرحله قبل بدون از دست دادن انتخاب پلتفرم |
| FR10 | Step 3 خلاصه import (تعداد مکالمات، تعداد duplicate های حذف‌شده طبق منطق Unit 04) را قبل از finalize نمایش دهد |
| FR11 | پس از تایید نهایی در Step 3، فرآیند ذخیره‌سازی دقیقاً از پایپ‌لاین موجود Unit 01/04 استفاده می‌کند |

## 4. Non-Functional Requirements

- کل فلو باید **کاملاً آفلاین** اجرا شود (بدون فراخوانی شبکه) — مطابق محدودیت پروژه.
- انتقال بین Step ها باید smooth باشد (بدون پرش/flicker محسوس)؛ جزئیات انیمیشن در سطح پیاده‌سازی تعیین می‌شود، نه در این Spec.
- فلو باید در Mobile/Tablet/Desktop مطابق breakpoint های تعریف‌شده در `ui-context.md` واکنش‌گرا باشد.
- آیکون‌های SVG باید vector (نه راستر) باشند تا در هر رزولوشن واضح بمانند.

---

## 5. UI Behavior

- **Step Indicator:** نمایش ۳ مرحله (۱-۲-۳) با نشان‌دادن مرحله فعلی، تکمیل‌شده، و باقی‌مانده — طبق رنگ‌های `--accent-primary` / `--text-muted` تعریف‌شده در `ui-context.md`.
- **کارت‌های پلتفرم (Step 1):** چیدمان grid (۲×۲ در desktop/tablet، تک‌ستونه در mobile طبق breakpoint موجود)، هر کارت شامل آیکون SVG + نام پلتفرم.
- **پیام "به‌زودی":** به‌صورت inline زیر کارت انتخاب‌شده یا در ناحیه پیام سیستم، با رنگ `--state-info` یا `--state-warning`.
- **پیام خطای mismatch (Step 2):** با رنگ `--state-error`، شامل توضیح کوتاه (مثلاً "فایل انتخابی مربوط به [پلتفرم تشخیص‌داده‌شده] است، نه [پلتفرم انتخابی شما]") و دکمه‌های "انتخاب فایل دیگر" / "بازگشت به انتخاب پلتفرم".
- **Step 3:** نمایش خلاصه به‌صورت لیست/کارت اطلاعاتی (تعداد مکالمات، duplicate ها) و دو دکمه: "تایید و Import" / "بازگشت".
- جزئیات دقیق تعامل (hover state دقیق، انیمیشن گذار) در سطح پیاده‌سازی توسط Cline تعیین می‌شود، نه در این Spec (طبق قاعده Spec باید implementation-agnostic باشد).

---

## 6. Validation

- Step 1: کاربر نمی‌تواند بدون انتخاب یک پلتفرم به Step 2 برود.
- Step 1: کاربر نمی‌تواند با پلتفرم بدون پارسر (ChatGPT/Claude/Gemini) به Step 2 برود.
- Step 2: فرمت فایل طبق قوانین موجود Unit 01 اعتبارسنجی می‌شود (بدون تغییر).
- Step 2: پلتفرم فایل آپلودی باید با انتخاب Step 1 مطابقت داشته باشد؛ در غیر این صورت import متوقف و خطا نمایش داده می‌شود.
- Step 3: کاربر باید صریحاً تایید کند؛ بستن یا navigate کردن از این مرحله بدون تایید، هیچ داده‌ای را ذخیره نمی‌کند.

## 7. Edge Cases

| سناریو | رفتار مورد انتظار |
|--------|---------------------|
| کاربر پلتفرم بدون پارسر انتخاب کند و روی کارت چند بار کلیک کند | پیام "به‌زودی" ثابت می‌ماند، دکمه ادامه غیرفعال باقی می‌ماند |
| کاربر در Step 2 فایلی آپلود کند که با هیچ پلتفرمی مچ نشود (فرمت ناشناس) | خطای عمومی "فرمت فایل شناسایی نشد" — بدون اشاره به پلتفرم خاص |
| کاربر از Step 2 به Step 1 برگردد و پلتفرم دیگری انتخاب کند | فایل آپلودشده قبلی پاک شود؛ کاربر باید دوباره آپلود کند |
| کاربر فایل خالی یا خراب آپلود کند | طبق منطق موجود Unit 01 مدیریت شود (بدون تغییر رفتار) |
| کاربر در Step 3 صفحه را رفرش/ببندد | هیچ داده‌ای ذخیره نشود؛ فلو باید از Step 1 دوباره شروع شود |
| تمام مکالمات فایل آپلودی duplicate باشند | Step 3 این مورد را به‌وضوح نشان دهد (مثلاً "0 مکالمه جدید، X مورد تکراری") |

## 8. Acceptance Criteria

- [ ] کاربر می‌تواند از بین ۴ پلتفرم (با آیکون SVG اختصاصی) یکی را در Step 1 انتخاب کند.
- [ ] انتخاب ChatGPT/Claude/Gemini بلافاصله پیام "به‌زودی" را نشان می‌دهد و مانع ادامه فلو می‌شود.
- [ ] انتخاب DeepSeek امکان رفتن به Step 2 را فراهم می‌کند.
- [ ] در Step 2، اگر فایل آپلودی با پلتفرم انتخاب‌شده مطابقت نداشته باشد، خطای شفاف نمایش داده و import متوقف می‌شود.
- [ ] در Step 2، اگر فایل با پلتفرم انتخابی مطابقت داشته باشد، کاربر بدون خطا به Step 3 می‌رود.
- [ ] Step 3 خلاصه صحیح (تعداد مکالمات جدید/تکراری) را نشان می‌دهد.
- [ ] پس از تایید در Step 3، داده‌ها دقیقاً طبق پایپ‌لاین موجود (Unit 01/04) ذخیره می‌شوند — بدون duplicate منطق.
- [ ] بازگشت بین مراحل، انتخاب‌های قبلی را (به‌جز فایل آپلودشده هنگام تغییر پلتفرم) حفظ می‌کند.
- [ ] فلو کاملاً بدون اتصال شبکه کار می‌کند.
- [ ] Unit 02 (Platform Detection) به‌صورت service مستقل قابل استفاده مجدد، بدون تغییر در رفتار قبلی‌اش، پیاده می‌شود.

## 9. یادداشت معماری (ADR Notes)

- Unit 02 از یک "Unit مستقل با UI خاص خودش" به یک **service داخلی قابل استفاده مجدد** تغییر ماهیت می‌دهد.
- Unit 01 هیچ تغییر منطقی نمی‌کند؛ فقط یک لایه UI جدید (Unit 08) جلوی آن قرار می‌گیرد.
- لوگوهای پلتفرم‌ها به‌صورت SVG مینیمال با رنگ برند طراحی می‌شوند (نه بازتولید دقیق لوگوی رسمی) به دلیل ملاحظات trademark.
