# Feature Spec: Local Chat Library

> **Unit:** 04 — Local Chat Library
> **Depends on:** Unit 03 (Modular Parsing System) — دریافت `UnifiedConversation` آماده برای ذخیره‌سازی
> **Maps to Feature:** #4 در فهرست Featureهای تأییدشده

---

## Goal

نگهداری مجموعه‌ای از مکالمات Parse‌شده (`UnifiedConversation`) در یک کتابخانه‌ی محلی پایدار (IndexedDB via Dexie)، همراه با Sidebar برای مرور و جابه‌جایی بین مکالمات، به‌گونه‌ای که داده بین بازدیدهای مختلف مرورگر باقی بماند.

> **مرز مسئولیت:** این واحد مسئول **ذخیره‌سازی، بازیابی، حذف، و لیست‌کردن** مکالمات است. رندر محتوای مکالمه با Theme اختصاصی پلتفرم (Unit 06)، نمایش متادیتای تکمیلی (Unit 05)، و جستجو (Unit 07) همگی خارج از Scope این واحدند و فقط از داده‌ی ذخیره‌شده در اینجا استفاده می‌کنند.

---

## User Flow

1. پس از موفقیت Unit 03، شیء `UnifiedConversation` به این واحد تحویل داده می‌شود.
2. سیستم بررسی می‌کند آیا این مکالمه از قبل در کتابخانه موجود است (تشخیص تکراری — جزئیات در بخش Validation).
3. اگر تکراری نبود، مکالمه در IndexedDB (از طریق Dexie) ذخیره و بلافاصله در Sidebar کتابخانه ظاهر می‌شود.
4. اگر تکراری تشخیص داده شد، به کاربر هشدار داده می‌شود و از او پرسیده می‌شود آیا مایل به افزودن مجدد (به‌عنوان رکورد جداگانه) است یا انصراف می‌دهد.
5. کاربر با کلیک روی یک آیتم در Sidebar، آن مکالمه را از IndexedDB بازیابی و به‌عنوان مکالمه‌ی «فعال» انتخاب می‌کند (نمایش واقعی محتوا در Unit 06 انجام می‌شود).
6. کاربر می‌تواند مکالمه‌ای را از کتابخانه حذف کند؛ پیش از حذف قطعی، یک Confirm Dialog نمایش داده می‌شود.
7. با بستن و باز کردن مجدد مرورگر، کتابخانه (تمام مکالمات ذخیره‌شده) بدون نیاز به Import مجدد در دسترس است.

## Functional Requirements

| # | Requirement |
|---|-------------|
| FR1 | سیستم باید یک Schema در Dexie تعریف کند که هر رکورد شامل کل `UnifiedConversation` + متادیتای کمکی برای Query (مثلاً `platform`, `importedAt`) باشد |
| FR2 | ذخیره‌سازی هر مکالمه باید یک عملیات Atomic در Dexie باشد (طبق لایه‌ی `storage/` در `architecture.md`) |
| FR3 | فقط لایه‌ی `storage/` مجاز به تعامل مستقیم با Dexie است؛ Component‌های UI هرگز مستقیماً IndexedDB را صدا نمی‌زنند (طبق `code-standards.md`) |
| FR4 | Sidebar باید فهرست تمام مکالمات ذخیره‌شده را نمایش دهد، با حداقل: عنوان (یا عنوان جایگزین در نبود آن)، آیکون/نشانه‌ی پلتفرم، و زمان Import |
| FR5 | انتخاب یک آیتم در Sidebar باید بدون Reload صفحه، مکالمه‌ی فعال را تغییر دهد |
| FR6 | سیستم باید امکان حذف یک مکالمه از کتابخانه را فراهم کند؛ حذف باید از IndexedDB به‌طور کامل پاک شود |
| FR7 | پیش از حذف قطعی یک مکالمه، یک Confirm Dialog باید نمایش داده شود؛ فقط با تأیید صریح کاربر حذف انجام می‌شود |
| FR8 | سیستم باید پیش از افزودن یک مکالمه‌ی جدید، بررسی کند که آیا مکالمه‌ی معادلی از قبل در کتابخانه موجود است. **الگوریتم دقیق این تشخیص (مثلاً بر اساس شناسه‌ی یکتا، یا ترکیبی از فیلدهای محتوایی) به لایه‌ی `storage/` واگذار می‌شود** و باید بتواند بدون تغییر در این Spec یا در Componentهای بالادست، تکامل یابد |
| FR9 | در صورت تشخیص تکراری، کاربر باید هشدار ببیند و بتواند بین «افزودن به‌هرحال» یا «انصراف» انتخاب کند؛ افزودن خودکار و بی‌صدا مجاز نیست |
| FR10 | این واحد نباید هیچ منطق مربوط به رندر محتوای مکالمه (Theme، حباب پیام) را در خود جای دهد — فقط داده را در اختیار Unit 06 قرار می‌دهد |

## Non-Functional Requirements

| # | Requirement |
|---|-------------|
| NFR1 | رندر Sidebar با ده‌ها مکالمه باید کمتر از ۲۰۰ میلی‌ثانیه طول بکشد (طبق `architecture.md`) |
| NFR2 | Sidebar باید در مقیاس تعداد زیاد مکالمه Responsive باقی بماند؛ راهکار بهینه‌سازی رندر (در صورت نیاز) در فاز Implementation و بر اساس داده‌ی واقعی عملکرد تعیین می‌شود، نه در این Spec |
| NFR3 | عملیات Storage (ذخیره، حذف، بازیابی) نباید UI را برای مدت محسوسی Block کند |
| NFR4 | داده باید بدون از دست رفتن، بین Sessionهای مختلف مرورگر باقی بماند (Persistence) |

## UI Behavior

| وضعیت | نمایش |
|-------|-------|
| **Empty State** | وقتی کتابخانه خالی است، راهنمای واضح برای Import اولین فایل (طبق `ui-context.md` → Shell Layout Patterns) |
| **Sidebar با آیتم‌ها** | هر آیتم حداقل عنوان، آیکون کوچک پلتفرم، و Timestamp را نمایش می‌دهد؛ امکان دسترسی به عملیات حذف برای هر آیتم فراهم است (جزئیات تعامل دقیق در فاز طراحی بصری/Implementation مشخص می‌شود) |
| **انتخاب آیتم** | برجسته‌سازی بصری آیتم فعال در Sidebar |
| **در حال حذف** | نمایش Confirm Dialog با متن واضح («این مکالمه برای همیشه حذف می‌شود») و دو گزینه (تأیید/انصراف) |
| **تشخیص تکراری هنگام Import** | Dialog هشدار با گزینه‌های «افزودن به‌هرحال» و «انصراف»؛ بدون تصمیم خودکار |
| **خطای Storage** | پیام خطای کاربرپسند طبق «Error Handling Standards» |

## Validation

| بررسی | نحوه‌ی اعمال |
|-------|----------------|
| **یکپارچگی `UnifiedConversation` ورودی** | قبل از ذخیره، ساختار پایه (فهرست پیام‌ها) باید معتبر باشد؛ این واحد به تولید صحیح Unit 03 اعتماد می‌کند اما یک بررسی سطحی Type Guard قبل از ذخیره‌سازی انجام می‌دهد |
| **تشخیص تکراری** | مسئولیت رفتاری (نه الگوریتمی) این واحد است: پیش از افزودن، بررسی وجود معادل انجام شود و نتیجه به کاربر گزارش شود (طبق FR8/FR9)؛ روش دقیق تشخیص در سطح `storage/` تصمیم‌گیری می‌شود |
| **تأیید حذف** | حذف بدون Confirm Dialog هرگز مجاز نیست |

## Edge Cases

| سناریو | رفتار موردانتظار |
|--------|-------------------|
| Import فایلی که به یک مکالمه‌ی موجود در کتابخانه معادل تشخیص داده شود | هشدار تکراری؛ کاربر تصمیم می‌گیرد (افزودن به‌هرحال یا انصراف) |
| نزدیک شدن به سقف Storage Quota مرورگر | هشدار پیش از خطای واقعی Storage |
| پر شدن کامل Quota حین ذخیره‌سازی | خطای کاربرپسند؛ مکالمه ذخیره نمی‌شود؛ کتابخانه‌ی موجود دست‌نخورده باقی می‌ماند (Atomic Operation) |
| حذف مکالمه‌ای که در همان لحظه به‌عنوان «فعال» انتخاب شده | پس از حذف، حالت فعال به Empty State یا یک مکالمه‌ی باقی‌مانده تغییر می‌کند |
| بسته‌شدن ناگهانی مرورگر حین عملیات ذخیره‌سازی | به لطف Atomic Operation در Dexie، یا مکالمه کامل ذخیره شده یا اصلاً ذخیره نشده؛ حالت نیمه‌ذخیره‌شده نباید رخ دهد |

## Acceptance Criteria

- [ ] مکالمات ذخیره‌شده پس از بستن و باز کردن مجدد مرورگر همچنان در دسترس‌اند
- [ ] کاربر می‌تواند بین چند مکالمه‌ی ذخیره‌شده در Sidebar بدون Reload صفحه جابه‌جا شود
- [ ] کاربر می‌تواند یک مکالمه را حذف کند؛ حذف فقط پس از تأیید در Confirm Dialog انجام می‌شود
- [ ] Import یک فایل معادل با مکالمه‌ی موجود، هشدار مشخص نمایش می‌دهد و افزودن خودکار/بی‌صدا رخ نمی‌دهد
- [ ] فقط لایه‌ی `storage/` مستقیماً با Dexie/IndexedDB تعامل دارد
- [ ] Sidebar با تعداد زیاد مکالمه (طبق NFR1/NFR2) Responsive باقی می‌ماند
- [ ] در صورت خطای Storage، پیام کاربرپسند نمایش داده می‌شود و کتابخانه‌ی موجود دست‌نخورده باقی می‌ماند
